# MEDEUS — Long Response, Sources and Downloadable Artifacts v1
**Date:** 2026-10-12 · **Status:** CANON_DECISION_RECORDED / WEBSITE_IMPLEMENTATION_NOT_STARTED

## User-approved product direction
MEDEUS is a **single-page website**, not a native app. In answer to the user's question about long, detailed responses and links vs downloadable files, **both** should be supported. The interaction must remain faithful to the existing exact master scene, ten core states, frameless UX and mobile/desktop responsive site.

## Long-answer presentation
1. The initial central idea or executive answer materializes from photons originating at the last genuine orb contact point (when interaction originates at the microphone, emission still begins inside the orb). Keep the user-accepted brief-answer photon choreography, not a multi-minute letter waterfall.
2. For long answers, transition to an integrated reading mode **within the same page**. The sphere becomes moderately smaller and remains visibly alive above the reading region; do not let it overlap the logo, text or microphone.
3. Paragraphs are revealed smoothly in sequence but remain immediately readable as real accessible text. Do not animate all glyphs of a long document one by one. Natural vertical scroll; do not forcibly auto-scroll while the reader is reviewing older sections. Preserve position when streaming updates arrive.
4. The microphone remains available to ask a follow-up without requiring a visible navigation bar, login or second page. Reading mode is a **presentation submode**, NOT an 11th canonical core state. `REVEALED` is the stable state for the visible answer; existing `DEEPENING` may reveal additional authorized/paid depth only after user request.

## Citations and outbound references
- Ground factual claims with **verifiable real citations** when retrieved from external sources. Inline subtle source markers open the original source; include publication/source title, timestamp or access date when available. Do not invent URLs, research citations, verification status or claim evidence unsupported by source content.
- A source section can be reached at the end of the answer. Citations for time-sensitive forecasts require provenance and cutoff. Label uncertainty and distinguish sourced facts from model-generated inferences.
- Outbound links are standard accessible hyperlinks, opened deliberately. Security: sanitize and validate destinations, `rel=noopener noreferrer` when appropriate; no arbitrary privileged script URLs, no tracking claims without disclosure.
- Optional attached reference documents/graphs and datasets are offered only when actually available and permissible to redistribute, with proper copyright/license constraints.

## Downloadable answer artifacts
- Offer **PDF** for formatted reading/sharing, **DOCX** for editable prose, **XLSX/CSV** for tabular data and calculations. Use TXT/Markdown only when relevant for portability.
- Generate a file **on demand**, especially for long studies/reports, rather than silently generating a file for every brief response.
- Do not display a working download action until server confirms generated bytes and delivery URL are valid. Show truthful file name/type/approximate size and generated-at date; preserve citations and uncertainty disclosures *inside the artifact*.
- Hosted files require explicit authorization/safe-scoped, unguessable, expiring URLs or equivalent download control; enforce data retention/privacy, licensing and payment entitlement rules. No account is required for MEDEUS but anonymous tokens require server-side validation.
- A download is the **same evaluated answer and evidence snapshot** presented on screen, not an independently modified or more confident reconstruction. File provenance and engine version are recorded for audit.
- Optional user-provided attachments (for questions) are a **different feature** from downloading system-generated answers; require explicit permissions, file-type and size restrictions, malware scanning, minimal retention and privacy review.

## UX controls without ordinary buttons
- In reading mode, lightweight in-scene text links/icons for `Sources`, `PDF`, `DOCX`, `Data` may appear unobtrusively at the end of relevant answers; avoid menu bars, floating panels or overly prominent CTA buttons.
- Only show controls for capabilities that genuinely work. Keyboard, screen reader, touch-target size, file-format choice and offline downloading must be usable on mobile; visual minimalism must not make citations/downloads inaccessible.
- Short replies must not be burdened with irrelevant file-format links.

## Truth boundary
- The current site renders local **demo copy** in a canvas; it has no verified long-response engine, progressive accessible document rendering, real citation resolution, live downloadable artifacts or production payments.
- `SPEC_RECORDED=true`; `LONG_RESPONSE_UI=NOT_IMPLEMENTED`; `SOURCE_CITATIONS=NOT_IMPLEMENTED`; `FILE_EXPORT=NOT_IMPLEMENTED`; `USER_ACCEPTANCE=OPEN`.
- Extend existing architecture; do not modify ASTRADELIA `8 + NOW` topology or bypass its evidence/forecast-system provenance and forward-validation policies.

## Acceptance gates
1. Demonstrate 200-, 1000-, and 3000-word answers on desktop and mobile, smooth scrolling, stable place, responsive orbit/core/mic layout, reduced-motion and screen reader accessibility.
2. Inline links verify real source page or file, citation maps to claim correctly, and no fabricated references; explicit provenance under forecast scenarios.
3. PDF/DOCX/XLSX generated only where appropriate/authorized, files open on Android/iOS/desktop, retain verifiable data and source citations.
4. No phantom download buttons or private-file leaks; anonymous ephemeral entitlement and clear retention.
5. Independently review that existing short-answer core animations and site master design remain unchanged.
